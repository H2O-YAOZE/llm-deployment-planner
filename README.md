# 部署推演 · LLM Deployment Planner

把模型部署需求转成可解释的卡数、服务器台数和采购费用，也可以从已有硬件反推能力，并与云端 API 费用比较。

面向 AI 售前、方案设计、预算评估，以及想理解“并发、上下文和生成速度为什么会影响硬件”的使用者。它是资源规划工具，结果属于估算。

## 已收录的数据

截至2026年10月14日的仓库快照，基础数据随源码一同公开：

| 数据类别 | 数量 | 口径 |
|---|---:|---|
| GPU / NPU及计算设备 | **22种** | 硬件型号/SKU；含8种NVIDIA、13种华为昇腾、1种海光 |
| 模型目录 | **99条** | 包括可作本地规划的模型，以及仅有API或待补全参数的条目 |
| API计费条目 | **67条** | 包含输入、缓存、输出及部分阶梯计费规则；不等于67家供应商 |

数据包括参数量、上下文、注意力结构、精度、显存、算力、带宽和费用等字段，并保留已有的来源、核验日期和待核验状态。收录数量不代表每个字段都已齐全，也不代表所有模型与硬件组合均已实测。

基础数据位于 [catalog.json](catalog.json)，浏览器和计算引擎使用其生成文件 [data.js](data.js)。线上面板使用同一套数据结构；新增资料需经过核验和计算适配，不能只增加展示条目而绕开计算路径。

## 能做什么

### 按需求选硬件

给出模型、精度、硬件、并发、最大输入与输出、每路生成速度、首 Token 时延，系统结合权重、KV Cache、显存、Prefill 和 Decode 计算候选部署方案。

例如：20路同时请求，每路输入80K、输出1K，生成至少30 Token/s，30秒内开始回答。系统估算需要多少卡、多少台服务器、采购费用多少，并解释每个结果怎么得到。

一个实例可以使用多张卡或跨服务器，多台服务器也可以运行多个独立实例。程序在已建模的候选布局中比较成本，并说明实例、卡数和台数的区别；不宣称找到所有真实运行时中的全局最优解。

### 已有硬件反推能力

固定已有服务器、每台卡数、模型和精度，再选择一个目标：最大并发、最高单路生成速度、最短首 Token 时延、最大输入或最大输出。

例如已有一台8卡服务器，可以固定生成速度和时延要求，观察缩短输入或输出后，并发上限如何变化。硬件是自变量，选定的需求指标是求解结果；这条路径不夹带 API 采购预算。

### 与云端 API 费用比较

根据对应模型的输入、缓存和输出计费规则估算 API 费用，与本地采购及运营支出比较，也支持按已有账单核算。

默认 API 工作量是每天12小时持续满并发，并使用填写的完整输入输出长度。这是指定负载下的预算，不是对实际账单的预测。未知价格或不明确的计费档位保留未知或范围。

### 拖动变量，看设备和采购费用变化

变量影响页固定 DeepSeek V4-Flash、FP8、H200 示例，分别提供并发、输入、输出、单路生成速度、首 Token 时延五项实验。基准为20路并发、80K输入、1K输出、30 Token/s、首 Token 30秒。

每项只改变一个变量，其余维持基准；拖动时实时重算卡数、台数和采购费用。整机采购有取整，所以费用可能呈阶梯变化。

### 统一数据目录与更新

模型、GPU/NPU规格、精度信息、部分公开测试及 API 价格集中保存在 `catalog.json`，`data.js` 由构建脚本生成。数据页、手动推演、问答和计算引擎使用同一份数据。

数据页展示最近检查与实际更新的时间，以及变动的模型、硬件和费用。支持手动扫描近60天新模型；可配置每日触发、每10天执行完整检查。资料来源以官方页面和官方模型仓库为主，AIHOT用于发现线索。未验证的结构、价格规则和大模型提案保留为待核验，不自动进入计算。

### 未核验适配，也能做资源估算

缺少某模型在某硬件上的适配文档，不等于禁止选择。硬件选项显示“估算，适配未核实”，问答也保留客户指定的硬件并提示误差风险。已有文档的组合注明相应依据，文档不等于当前需求已实测。

Kimi K3、DeepSeek V4.1-Flash提供显式架构参考估算：使用替代的存储与注意力假设，具体条件可展开查看。它们不是原生运行时预测，也不是已适配证明。详情见 [估算边界](UNVERIFIED-ESTIMATES.md)。缺少公开结构、权重参数或硬件规格时，不编造数字。

### 使用自己的采购报价

可以反复修改单卡报价、服务器平台费用和相关财务参数。内置价格只是参考，不同供应商、企业和采购批次的报价应由使用者填写。

## Jev、DeepSeek与程序怎样分工

```text
客户描述需求
    ↓
Jev：判断表达含义与推演方向
    ↓
DeepSeek：整理技术参数、保留已确认条件、补齐缺项
    ↓
程序：校验单位、字段和目录，确认需求，执行正向/反向计算
    ↓
卡数、台数、费用与可查看的计算过程
```

Jev前置判断“人数”是在线人数还是并发、“快”是首 Token 更快还是生成更快，以及是在购买设备还是评估已有设备。DeepSeek负责对话和参数整理，具体服务模型由服务端配置决定。被测算的部署模型与问答使用的模型是两个概念。

**硬件数量和费用由程序计算，不由 Jev 或 DeepSeek直接猜测。**未配置模型密钥时，手动推演仍可使用。

## 本地运行

需要 Python 3.10+；服务代码使用标准库。Node.js用于运行计算回归测试，不是启动网站的必要条件。

```bash
python scripts/build-catalog.py --check
python server.py --port 8095
```

打开 `http://127.0.0.1:8095/`。手机自适应使用同一界面。问答服务配置见 [ADVISOR_API.md](ADVISOR_API.md)，Jev接入见 [CLAUDE-CODE-接入Jev.md](CLAUDE-CODE-接入Jev.md)。

将 `.env.example` 复制为 `.env.local`，填写自己的私有配置。对外监听时必须配置登录认证，建议配合 HTTPS 反向代理。仓库不包含密钥、线上私有配置或登录信息。

```bash
# 不调用资料提取模型，手动检查官方来源
python scripts/catalog_sync.py --no-llm --scan-days 60
```

自动更新的范围、安装方式、资料提取配置与恢复方法见 [DATA-AUTO-UPDATE.md](DATA-AUTO-UPDATE.md)。公开来源可能不可访问，源文件结构也可能变化；检查失败不等于已经更新。

## 计算边界与贡献

资源规划会受模型架构、量化、推理框架、调度、互连和实际负载影响。参考估算可能有较大偏差，不能代替部署验收、压测或供应商报价。性能测试有条件范围，不能无条件套到其他硬件、精度和上下文长度。

欢迎贡献带来源的模型或硬件资料、完整条件下的压测、报价说明，以及计算和界面改进。修改基础数据时请同步核对计算适配，并运行 `python scripts/build-catalog.py`，保持目录与浏览器数据一致。

本项目代码采用 MIT 许可证。第三方组件、模型、数据来源及其使用受各自许可和条款约束；模型目录不包含模型权重。ECharts许可证保留在 `vendor/echarts-6.1.0/`。
