# 计算审查与边界修复 · 2026-10-15

## 这次场景

DeepSeek V4-Flash、910C、INT8；100并发，输入1,000,000 Token、输出1,000 Token，首Token不超过30秒，单路生成不低于50 Token/s。

输入输出合计1,001,000，未超过目录中的原生上下文1,048,576。输入有效。

现有搜索检查29种EP/Attention TP/DP分组；不包含上下文并行或Prefill/Decode分离。最快单路首Token估算106.4879秒，其中专家矩阵0.4059秒、非专家矩阵8.5805秒、Attention97.4013秒，另有传输与阶段开销。这些数值只针对目录参数和现有公式，不是910C实测上限。

## 修复范围

- 将输入无效、搜索内未找到方案、估算可行分开返回。所有未找到方案的结果均明确搜索范围及未覆盖方案，不声称物理不可行或全局最优。
- 显存和生成速度能独立算出的配置保留为部分结果，明确不满足全部要求、不能相加、不能直接采用。该例显存部分16卡/2台，显存加生成速度部分32卡/4台；都没有满足30秒首Token。
- 反向求解失败不再把用于诊断的候选放进`chosen`，也不返回采购费用或可采用按钮。候选仍保存在候选列表，便于解释。
- 反向输入/输出上限使用与正向一致的上下文字段回退，避免兼容目录条目能正向计算却反向失败。
- 输入输出超过上下文时展示加法、合计及上限，模型激活参数超过总参数时展示冲突值。
- 修正测试中已过时的模型数量和“目录模型一律不可算”断言；保留数学不变量与不完整数据阻断检查。

## 尚未完成的计算能力

**本次没有实现上下文并行和Prefill/Decode分离的完整容量与定价模型。** 因此，这次发布不能宣称已经找到截图场景的完整配置或最低采购价。

2026-10-15重新读取的vLLM-Ascend官方V4-Flash文档有`enable_dsa_cp`、1M序列和PD分离示例；文档开头同时说明PD分离部分是示例/参考设计，不推荐直接生产使用。SGLang V4代码包含CP状态切分、集合通信及缓存处理。存在这些实现不等于已证明本场景的30秒目标。

完整扩展需要核对具体运行版本及量化路径，明确每条请求的分片数、Attention组、专家组、缓存布局、通信数据量与有效带宽、P/D资源分配、缓存搬运及排队时间，并以同负载测试或清楚标注的规划假设校准。不能把106秒直接除以卡数，也不能把HCCS/NVLink总带宽当作跨服务器网络带宽。
